# lx Subagent：把任务交给合适的执行上下文

## 前置条件

- 找到当前计划，并确认 `plan_status: approved`。
- 每个任务必须有清晰目标、输入、输出、验收条件、测试切面和完成定义。
- 没有批准计划或任务描述不完整时停止，不自行补写业务需求。

## 默认串行

- 一次只派发一个任务。
- 任务完成后读取 diff、运行验收命令，再决定下一个任务。
- Subagent 不得扩大任务范围、重写无关文件或自行批准计划。
- 失败时返回证据、假设和建议，不通过删除测试或放宽验收来“修绿”。

## 允许并行的条件

只有同时满足以下条件，才建议并行：

- 任务之间没有阻塞依赖；
- 修改文件集合不重叠；
- 不共享会被同时写入的生成物、配置或迁移；
- 每个任务都有独立验证命令；
- 用户明确接受并行带来的合并和复核成本。

派发前先给用户一张简短的任务关系表，标出串行边、并行边、文件边界和合并风险。

## 收尾

所有任务完成后，汇总测试结果、未解决风险、变更文件和需要用户审阅的决策。不要自动提交、推送或创建 Pull Request。
