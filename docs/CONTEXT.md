# lx-cursor-workflow 术语表

## 工作流

从需求澄清到可验证实现的一组有顺序、有产物、有确认门的步骤。它不是一次性提示词，也不是自动批准代码修改的代理。

## Grill

逐个问题推进的决策树访谈。目标是消除歧义、发现依赖和明确边界；不是让 Agent 替用户做产品决策。

## Brainstorm

在问题和约束已足够清晰后，稳定地产生多个不同方向的候选方案，再按约束比较。发散的是方案，固定的是过程。

## Writing plan

把已确认的方案转成有依赖关系、验收条件和测试切面的实施计划。它不等于代码实现。

## Seam / 测试切面

观察外部行为的最高公共边界。优先测试用户或调用者能看到的行为，不测试私有实现细节。

## Plan gate / 计划确认门

从文档阶段进入代码阶段前的人工确认。未确认的计划不得触发 TDD 或 Subagent 修改业务代码。

## Vertical slice / 垂直切片

一次只完成一个可观察行为：先写一个失败测试，再写足够通过的最小实现，然后进入下一切片。

## Subagent

为单个任务提供独立上下文的执行者。默认串行；只有任务互不依赖且文件不重叠时才允许并行。

## 冲突

安装目标中已有同名 `lx-*` 目录，且内容与待安装版本不同。冲突不是覆盖许可；安装器遇到冲突会停止并要求人工处理。
