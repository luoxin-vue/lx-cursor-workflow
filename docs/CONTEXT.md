# lx-cursor-workflow 术语表

## 工作流

从新需求或 Bug 复现到可验证实现的一组有顺序、有产物、有确认门的步骤。它不是一次性提示词，也不是自动批准代码修改的代理。

## 请求分类

进入工作流后的第一步：已有行为不符合预期时走 Bug 修复线；新增能力或改变已确认规则时走需求线。混合请求拆成两条线，分别形成计划和确认门。

## Bug 修复线

专门处理已有行为的错误、回归、异常、性能退化和测试失败。顺序是固定复现事实、定位根因、建立回归测试、制定最小修复、验证结果。没有复现证据时，状态保持为未复现，不把猜测性修改报告为修复完成。

## 回归测试

针对已发生 Bug 的外部行为测试。它先在修复前稳定失败，再在最小修复后通过，用来证明问题被解决且不会轻易复发。

## 根因证据

能把现象连接到具体触发条件、直接原因和缺失约束的可观察证据，包括失败测试、日志、请求时序、状态变化或最小复现结果。单纯“看起来像”不是根因证据。

## Grill

逐个问题推进的决策树访谈。目标是消除歧义、发现依赖和明确边界；不是让 Agent 替用户做产品决策。

## Brainstorm

在问题和约束已足够清晰后，稳定地产生多个不同方向的候选方案，再按约束比较。发散的是方案，固定的是过程。

## Writing plan

把已确认的方案转成有依赖关系、验收条件和测试切面的实施计划。它不等于代码实现。

## Seam / 测试切面

观察外部行为的最高公共边界。优先测试用户或调用者能看到的行为，不测试私有实现细节。

## Plan gate / 计划确认门

从文档阶段进入代码阶段前的人工确认。未确认的计划不得触发 TDD 或 Subagent 修改业务代码。

## Vertical slice / 垂直切片

一次只完成一个可观察行为：先写一个失败测试，再写足够通过的最小实现，然后进入下一切片。

## Subagent

为单个任务提供独立上下文的执行者。默认串行；只有任务互不依赖且文件不重叠时才允许并行。

## 冲突

安装目标中已有同名 `lx-*` 目录，且内容与待安装版本不同。冲突不是覆盖许可；安装器遇到冲突会停止并要求人工处理。
